## Critères de fin et vérifications à exécuter

### S-101-C01

La carte est un pass membre/fidélité, jamais identité/assurance/authentification ; ajout est proposé seulement pour plateforme/appareil compatibles.

- Oracle : **V3**.
- Vérification à exécuter : Créer deux instances de fixture et lire leur nature simulée ; une plateforme incompatible offre accès Wallet sans faux ajout natif.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-101.plan.md#s-101-c01)

### S-101-C02

Champs nom consenti/ID/statut, solde ou niveau daté, avantage actif, accès rapide et assistance sont minimaux et dérivés des objets canoniques.

- Oracle : **V2**.
- Vérification à exécuter : Inspecter payload et QR : aucun contrat, patrimoine, médical ni secret ; nom absent si non consenti.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-101.plan.md#s-101-c02)

### S-101-C03

Deep link vers Wallet exige l’authentification CoverView/WorkOS ; le pass n’est jamais un facteur de connexion autonome.

- Oracle : **V2**.
- Vérification à exécuter : Ouvrir le lien sans session : parcours AuthKit ; présenter le QR ne donne pas accès à un dossier.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-101.plan.md#s-101-c03)

### S-101-C04

Chaque instance peut être mise à jour, suspendue/révoquée ou renouvelée ; compte fermé/fraude/perte invalide les opérations autorisées.

- Oracle : **V3**.
- Vérification à exécuter : Révoquer appareil A depuis Wallet/Admin autorisé ; A est refusé, B garde son état propre et historique conservé.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-101.plan.md#s-101-c04)

### S-101-C05

Jetons sont validés serveur avec expiration/portée/rotation et anti-réutilisation ; refus explicite hors ligne ou hors portée pour opération sensible.

- Oracle : **V2**.
- Vérification à exécuter : Tester jeton expiré, forgé, utilisé et destiné à un autre partenaire : tous refusés sans fuite d’information.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-101.plan.md#s-101-c05)

### S-101-C06

Événements et journal permettent reprise, état par appareil et erreurs de mise à jour ; révoquer ne supprime pas le ledger/historique métier.

- Oracle : **V2**.
- Vérification à exécuter : Rejouer mise à jour/révocation : une transition logique, état persisté et zéro suppression de l’historique.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-101.plan.md#s-101-c06)
