## Parcours et travail attendu

1. Demander une tâche de rappel ou un brouillon depuis un objet identifié.
2. Vérifier l’aperçu typé, résoudre une ambiguïté puis confirmer le payload exact si requis.
3. Suivre résultat/échec, reprendre depuis une autre vue et annuler une opération compensable.

Applications : `api`, `admin`. Relier UI, API, autorisation, persistance, erreurs et reprise selon le parcours ; traiter vide, chargement, succès, échec, refus, objet absent et session expirée lorsqu’applicables.

**Données et invariants**

- Registre d’actions/version/schémas et niveaux lecture/brouillon/faible impact/confirmation/interdiction.
- Action plan immuable avec hash/payload/révisions, approbation datée, idempotency key, exécution, résultat et compensation liée.

Tout nouvel objet privé persistant déclare sa catégorie, son propriétaire et ses règles d’export/rétention via S-130/S-131, ou leur contrat manifeste si ces services ne sont pas encore livrés. Aucune durée légale n’est inventée ; la campagne finale S-139 vérifie toutes les catégories.

## Critères de fin et vérifications à exécuter

### S-095-C01

Le LLM ne possède ni SQL ni écriture directe : seules actions versionnées et schémas validés atteignent les services domaine.

- Oracle : **V2**.
- Vérification à exécuter : Rejeter outil inconnu, paramètre supplémentaire dangereux et ID d’un autre tenant avant tout effet.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-095.plan.md#s-095-c01)

### S-095-C02

Lecture, brouillon, faible impact réversible, confirmation sensible et interdiction/escalade sont distingués par une politique approuvée.

- Oracle : **V2**.
- Vérification à exécuter : Classer tâche/note, email, montant, publication, suppression, signature et mouvement massif ; tous les sensibles passent par confirmation.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-095.plan.md#s-095-c02)

### S-095-C03

Créer tâche/rappel, note/tag et brouillon depuis contexte fiable produit les objets canoniques et liens ; homonyme/date ambiguë demande résolution.

- Oracle : **V3**.
- Vérification à exécuter : Préparer le rappel LPP et brouillon AXA ; tâche persistée après action autorisée, email encore non envoyé.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-095.plan.md#s-095-c03)

### S-095-C04

L’aperçu expose objets, anciennes/nouvelles valeurs, destinataires, échéances, documents et conséquences ; modification substantielle invalide l’accord.

- Oracle : **V2**.
- Vérification à exécuter : Changer destinataire ou montant après confirmation : l’exécution est refusée et réclame nouvel aperçu/accord.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-095.plan.md#s-095-c04)

### S-095-C05

Identité, permissions, contraintes et idempotence sont recontrôlées au moment d’exécuter et dans le worker.

- Oracle : **V2**.
- Vérification à exécuter : Retirer le droit après preview puis confirmer : aucun effet ; reprendre le même ID après timeout ne crée pas une seconde tâche.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-095.plan.md#s-095-c05)

### S-095-C06

Résultat, erreurs, actions proposées/exécutées et annulation ou compensation sont visibles et reliés à l’original, sans prétendre annuler un effet irréversible.

- Oracle : **V3**.
- Vérification à exécuter : Créer une note réversible puis annuler ; voir les deux événements ; un email local envoyé propose seulement la compensation autorisée.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-095.plan.md#s-095-c06)

### S-095-C07

Journal conserve paramètres autorisés, contexte, décision, approbation, version, erreur/résultat et métriques de refus sans exposer contenu privé inutile.
