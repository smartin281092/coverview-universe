2. Diagnostiquer job et tentative via correlation ID.
3. Relancer ou restaurer en cible isolée.

Applications : `api`, `client`, `admin`. Relier UI, API, autorisation, persistance, erreurs et reprise selon le parcours ; traiter vide, chargement, succès, échec, refus, objet absent et session expirée lorsqu’applicables.

## Critères de fin et vérifications à exécuter

### S-132-C01

Les travaux longs exposent progression, retry borné et dead-letter queue ; un opérateur reprend le travail avec les mêmes clés d’idempotence.

- Oracle : **V2**.
- Vérification à exécuter : Couper un worker entre effet et accusé ; redémarrer et vérifier un seul effet, progression stable et reprise de DLQ sans action perdue.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-132.plan.md#s-132-c01)

### S-132-C02

Les uploads appliquent quotas et antivirus ; les erreurs restent visibles dans le dossier et ne déclenchent pas l’analyse d’un fichier interdit.

- Sources : [ancrages exacts du critère dans le plan](../plans/S-132.plan.md#s-132-c02)

- Oracle : **V3**.
- Vérification à exécuter : Restaurer DB et objets dans une nouvelle cible de test ; comparer comptes, hashes et liens, mesurer durée/perte sans revendiquer un objectif non convenu.
- Sources : [ancrages exacts du critère dans le plan](../plans/S-132.plan.md#s-132-c03)

- Sources : [ancrages exacts du critère dans le plan](../plans/S-132.plan.md#s-132-c04)
