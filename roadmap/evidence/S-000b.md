## Décisions d’implémentation autorisées

- API Fastify propriétaire du module `identity`, du profil canonique et des sessions opaques. Unicité sur l’identité WorkOS, jamais fusion par email ; données personnelles bornées au propriétaire (ADR-0002).
- Callback unique `http://127.0.0.1:4100/auth/callback` en local. Destination finale choisie parmi Wallet `http://127.0.0.1:4101/account`, équipe `http://127.0.0.1:4102/account`, www `http://127.0.0.1:4103/account`. Aucune URL de retour libre. HTTP accepté uniquement sur loopback local ; HTTPS exigé hors local. Aucun DNS ni déploiement engagé.
- Code + PKCE ; transaction courte en base, state lié à un cookie HttpOnly de navigateur et consommé atomiquement. Les secrets PKCE transitoires sont chiffrés au repos ; aucune clé réelle écrite par l’agent (ENV-05).
- Cookie de session opaque HttpOnly, SameSite=Lax, host-only de l’API ; Secure en HTTPS. Hash seul persisté. CORS exact avec credentials et CSRF sur mutations. Profil minimal exposé, pas de token WorkOS dans JavaScript.
- La session locale vérifie sa révocation et la session distante à chaque accès. Appels bornés, refus fermé en cas d’indisponibilité ou de liste distante tronquée. Pas de refresh token conservé : les tokens issus du callback sont vérifiés en mémoire puis abandonnés ; une nouvelle authentification sera nécessaire à l’expiration absolue locale. Ce choix évite un second mécanisme de rotation.
- Révocation locale atomique avant les effets externes ; distinguer la révocation distante complète et en attente. Aucun succès global simulé après erreur WorkOS. Les callbacks en vol doivent être invalidés par une génération de sessions utilisateur.
- Habilitation locale explicite absente par défaut, relue à chaque requête. Un rôle transmis par le navigateur ou une organisation WorkOS ne la crée jamais. Une preuve MFA liée à la session est nécessaire ; l’inscription d’un facteur ou la méthode MagicAuth n’en constitue pas une.
- Dépendances ajoutées : SDK Node WorkOS officiel (API fournisseur et validation de session), plugins Fastify cookie (parsing/attributs robustes) et rate-limit (anti-abus). Paquets officiels MIT, versions stables du registre npm contrôlées avant ajout. Audit final sans vulnérabilité connue ; aucune bibliothèque d’authentification concurrente.

Ces décisions précisent le plan existant dans le mandat PROG-23 ; elles ne changent pas son objectif et ne prouvent aucun oracle externe. Les durées techniques par défaut sont réversibles et ne sont pas des durées juridiques de rétention.
