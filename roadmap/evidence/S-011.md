1. Premier typecheck/build www et quatre tests du garde : succès. La revue détecte ensuite le garde limité aux chiffres suivis de devise/%, et un oracle de miroir excluant le YAML cité. Garde étendu aux formats préfixés, mots usuels et métadonnées ; refus testés. Lecteur indépendant de sources accepte les deux formes YAML, les 18 miroirs sont contrôlés.
2. Prettier ne possède pas de parser Astro dans la stack existante. Les fichiers TS/MDX/CSS ont été formatés ; l’appel ciblant explicitement Layout.astro a retourné cette limite, sans modification du fichier par Prettier. Astro Check et ESLint valident le code ; aucune dépendance ajoutée pour le formatage.
3. Frontières : un export du schéma sans consommateur signalé par knip. Export retiré, schéma exécuté par la même fonction de validation ; frontières/knip passent ensuite. Avertissement préexistant du catalogue importé depuis Astro maintenu.
4. Premier E2E complet : **22/25**. Deux oracles supposaient le libellé générique « en préparation » là où Retire/Miles annoncent l’indisponibilité précise ; assertions adaptées à chaque état sans retirer les refus de formulaire. Troisième échec réel : retour FAQ vers l’index racine au lieu de page 2, et focus natif non restauré.
5. Correction du retour : index propriétaire calculé depuis la pagination, ancre sur le lien réel de la carte. Oracle conserve retour navigateur URL/visibilité, puis vérifie distinctement retour explicite page 2 + hash + focus. Typecheck/build, revue indépendante et deuxième recette complète **25/25** passent. `check:www` passe sur les deux builds ; JSON final conservé.
6. La recette identité a réécrit sa capture suivie S-000b. Seul ce fichier issu de nos tests a été restauré depuis HEAD pour préserver la preuve antérieure. Aucun reset, nettoyage ou stash d’autrui.
