## Dépendance et essais

Sharp **0.35.4** est déclaré directement dans `www` pour le service d’optimisation d’images Astro. Il était déjà transitif dans le lockfile ; aucun paquet concurrent, aucune version existante mise à jour. Nom exact et provenance [officielle Sharp](https://github.com/lovell/sharp), licence Apache-2.0, version publiée le 26 août et métadonnées npm contrôlés ; environ 960 kB pour le paquet JS, binaires natifs déjà transitifs. [Astro recommande Sharp pour ce service](https://docs.astro.build/en/guides/images/) ; Node stdlib ne fournit pas cet encodage. Aucun traitement d’image distante ou d’upload, seulement le fond local connu. Audit npm final sans vulnérabilité connue ; pas de scan d’images Docker revendiqué.

- Premier lancement pnpm : chemin `bin/pnpm.cjs` inexistant dans la distribution native. Correction vers le `pnpm.exe` indiqué par le checkpoint, sans modification globale.
- Deux builds image ont échoué : Sharp absent de la résolution de l’app, puis jonction pnpm vers un répertoire sans suffixe de peer inexistant malgré l’ajout. Diagnostic direct de l’import et du lien ; `pnpm --filter www update sharp` a recalculé la même version avec son peer `@types/node`, sans édition manuelle du lockfile. Import/build et installation frozen passent ensuite.
- Une application initiale de patch a été refusée avant écriture pour deux opérations sur le même fichier ; patch séparé, aucun état partiel.
- Le premier passage complet navigateur a échoué pendant l’attente brute de `document.fonts.ready`, contexte détruit lors du rechargement de développement après build. Attente Playwright de l’état `loaded`, mêmes assertions de géométrie/focus ; passage complet suivant **20/20**. Aucun test désactivé ni seuil relevé.
- Le connecteur de navigateur intégré n’a pas démarré (chemin de ses assets noyau introuvable). Les vrais parcours et captures ont été exécutés via le Chromium Playwright installé ; images ouvertes et inspectées par le propriétaire.
